# Working Rules

These rules apply to work on the `rewrite` branch.

- Keep answers short unless more detail is requested.
- Do not decide architecture without discussing it first, unless explicitly
  asked to make the decision for the current task.
- Permission such as “implement it like you want” applies only to that task.
- Temporary rule changes apply only to the current situation. Permanent rule
  changes must be stated explicitly.
- Stay within the current feature. Do not include other previously discussed
  features without explicit direction.
- When discussing a feature, do not expand into the implementation of external
  APIs, websites, or other tools merely because they run on the same machine.
- Do not overcomplicate implementations.
- Add abstractions only when they solve a demonstrated need.
- Reuse existing code where practical.
- If reuse would require substantial rewriting, discuss it before proceeding.
- Examples and proposals are not approved decisions.
- Do not implement a proposal until it has been explicitly approved.
- Do not commit unless explicitly requested.
- Before starting a new feature, report existing uncommitted feature work.
